That taught me how to own outcomes, manage a wide range of stakeholders, and stay calm when something breaks in production (commercially, at least).

It actually started even earlier: I taught myself to **build computers**, then taught myself to **code and ship applications**. The deeper I went, the clearer the direction became.

### 🔐 Why I moved from writing code to DevOps

The more I built, the more I realised the hard part isn't writing the code — it's shipping it safely and keeping it running. AI has made writing code faster than ever, but every extra line is extra attack surface, and I kept hitting the same wall: **speed was outpacing security.** That's what pulled me toward DevOps and DevSecOps. A few examples that pushed me:

- **AI writes code fast — too fast to review by hand.** Instead of eyeballing every change, I started treating security as a pipeline stage: SAST, dependency scanning and secret detection running automatically on every push (Trivy, Dependabot, gitleaks).
- **AI loves pulling in dependencies.** A project's supply chain balloons quickly. My fix was automated dependency and container-image scanning in CI, so nothing ships with a known CVE.
- **Hardcoded secrets and config drift.** I moved secrets out of code and into managed stores, with pre-commit hooks and secret scanning to catch leaks before they ever reach a repo.
- **"Works on my machine."** Docker made my environments reproducible and auditable instead of a mystery.
- **Manual, risky deploys.** CI/CD pipelines with automated tests and gated deployments meant safer releases — and easy rollbacks when something went wrong.

Writing the app was fun. Making it reliable, secure and repeatable is the part I actually want to do for a living.
